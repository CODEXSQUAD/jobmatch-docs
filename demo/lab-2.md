**Координатор:** Матвей.

**Статус:** структура выступления готова; технические шаги и ссылки заполняются фактами после выполнения зависимых задач.

## Цель показа

За 7–10 минут объяснить проблему, границы учебного MVP, объектную модель и командный процесс, затем показать минимальную работающую цепочку:

`браузер → React → ASP.NET Core API → PostgreSQL → список вакансий`.

## Сценарий выступления

### 1. Проблема и гипотеза — 40 секунд

JobMatch помогает соискателю осознаннее выбирать вакансии за счёт ограниченного числа откликов. Для работодателя ожидаемый эффект — меньше нерелевантных заявок. Это продуктовая гипотеза, а не уже доказанный результат; будущая метрика — доля откликов, завершившихся приглашением.

### 2. Границы MVP — 60 секунд

Три роли: гость, соискатель, работодатель. Главный путь: работодатель публикует вакансию → соискатель находит её и отправляет резюме → списывается одна единица → работодатель приглашает или отказывает → соискатель видит статус.

В рабочую версию входят UC-01–UC-10. Не входят платежи, реклама, чат, AI-подбор, импорт вакансий, мобильное приложение и административный интерфейс.

### 3. Ключевые правила — 60 секунд

- 5 бесплатных откликов на московский календарный день, без переноса остатка;
- один кандидат может откликнуться на вакансию один раз, даже после отзыва;
- отзыв или отказ не возвращает лимит;
- отклик возможен только на опубликованную вакансию с заполненным резюме;
- отклик хранит снимок резюме;
- создание заявки, списание и журнал выполняются одной транзакцией;
- повторный или конкурентный запрос не создаёт двойного списания.

Сразу оговорить: правила ожидают подтверждения Клима, Альберта и команды.

### 4. ERD — 90 секунд

Открыть [ERD](../architecture/erd.md) и показать четыре области:

1. учётная запись и роль — `User`, `CandidateProfile`, `CompanyMember`;
2. резюме — `Resume`, `WorkExperience`, `Education`, `Skill`, `ResumeSkill`;
3. вакансии и отклики — `Company`, `Vacancy`, `VacancySkill`, `Application`;
4. лимит — `CreditAccount`, `CreditTransaction`.

Обратить внимание на ограничения: уникальный email, одно резюме, один отклик кандидата на вакансию, неотрицательный баланс и сохранение заявки после закрытия вакансии. Пояснить, что `resume_snapshot` — версия отправленного резюме, поэтому последующее редактирование не меняет уже отправленную заявку.

### 5. API и интерфейс — 60 секунд

Альберт показывает согласованные пути и схемы из `api/openapi.yaml`, Влад — соответствующие экраны в Figma. Проверить, что названия статусов, фильтров и обязательных полей совпадают с MVP и словарём данных.

До появления этих материалов говорить: «контракт/макеты в работе по задаче», а не демонстрировать пустой файл как готовый результат.

### 6. Работающая основа — 2–3 минуты

Из каталога `jobmatch-backend` выполнить:

```bash
docker compose up --build
```

Затем показать по порядку:

1. `GET /health` возвращает успешный статус;
2. PostgreSQL-контейнер имеет состояние healthy;
3. `GET /api/vacancies` возвращает вымышленные вакансии из БД;
4. страница каталога отображает эти вакансии;
5. после перезапуска контейнеров данные сохраняются в volume.

Точные URL, имена сервисов и ожидаемые ответы внести сюда только после появления `compose.yaml`, backend README и OpenAPI.

### 7. План до лабораторной №3 — 40 секунд

Показать [roadmap](../planning/roadmap.md): на второй неделе — авторизация, резюме, компания, вакансии и каталог; на третьей — отклики, лимиты, кабинеты, статусы и проверки. Последние два дня оставлены на исправления и репетицию.

### Чистый технический запуск

Проверку выполняют Игорь и Клим в Linux-окружении с 8 ГБ RAM; Матвей фиксирует факт и обнаруженные проблемы.

| Проверка | Команда/действие | Ожидаемый результат | Факт |
|---|---|---|---|
| Версии | `docker version` и `docker compose version` | доступны Client, Server и Compose | не проверено |
| Чистая сборка | `docker compose build --no-cache` | все образы собраны без ошибок | не проверено |
| Запуск | `docker compose up -d` | frontend, API и БД запущены | не проверено |
| Состояние | `docker compose ps` | сервисы running/healthy | не проверено |
| Health | открыть `/health` | HTTP 200 и ожидаемое тело | не проверено |
| API | открыть `/api/vacancies` | минимум одна вымышленная вакансия | не проверено |
| UI | открыть каталог | данные API видны на странице | не проверено |
| Сохранение | перезапустить Compose без удаления volume | данные остались | не проверено |
| Остановка | `docker compose down` | контейнеры остановлены, volume сохранён | не проверено |

Не выполнять `docker compose down -v` во время проверки сохранения: ключ `-v` удаляет данные.
