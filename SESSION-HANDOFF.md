## 3. Идея продукта

Из README CODEXSQUAD: JobMatch — поиск работы на российском рынке с ограничением массовых нерелевантных откликов. Есть бесплатный запас; дополнительные отклики предполагается получать за рекламу или покупку.

Для учебного MVP предложено реализовать **бесплатный лимит**. Реальные платежи, реклама, чат, AI-подбор, импорт вакансий, мобильное приложение и административный интерфейс отложены.

Главный сценарий: работодатель публикует вакансию → соискатель находит её → отправляет резюме → расходуется один отклик → работодатель приглашает или отказывает → соискатель видит статус.

Снижение нерелевантности — гипотеза продукта, а не доказанный результат. Возможная будущая метрика — доля откликов, заканчивающихся приглашением.

## 5. Предложенный стек, пока не утверждённый командой

- Frontend: React, TypeScript, Vite; React Router, TanStack Query, Material UI.
- Backend: C#, ASP.NET Core Web API, .NET 10 LTS.
- БД: PostgreSQL, Entity Framework Core, Npgsql; миграции в backend.
- Пользователи: ASP.NET Core Identity; cookie-сессия для сайта на одном домене с защитой от CSRF.
- API: OpenAPI и Swagger UI.
- Запуск: Docker Compose и Nginx.
- Документы: Markdown, Mermaid, Figma.
- Проверки функциональности: xUnit, позднее основные сквозные сценарии Playwright.

Архитектура: один backend с модулями, одна БД. Не предлагать микросервисы, Kubernetes, Kafka и другие дополнительные системы без конкретной потребности.

## 6. Черновик MVP и правила для обсуждения

Пользователи: гость, соискатель, работодатель. Предложено выбрать одну роль при регистрации; один соискатель имеет одно резюме, один работодатель — одну компанию.

UC-01–UC-10: регистрация/вход/выход; резюме; компания; создание/публикация вакансии; каталог с поиском/фильтрами/пагинацией; карточка вакансии; отклик; кабинет соискателя/отзыв; обработка работодателем; закрытие вакансии.

Предлагаемые правила, которые ещё надо утвердить:

- 5 бесплатных откликов на московский календарный день, без переноса остатка. Лимит — настройка.
- Один отклик кандидата на вакансию, даже после отзыва.
- Отзыв и отказ не возвращают единицу.
- Отклик возможен с заполненным резюме на опубликованную вакансию.
- Сохраняется снимок резюме при отправке.
- Создание отклика, списание и журнал — одна транзакция.
- Повтор запроса не вызывает второй отклик или списание.
- Два конкурентных запроса при остатке 1 создают максимум один отклик.
- Доступ к заявкам проверяется сервером по пользователю и компании.

Статусы вакансии: Draft → Published → Closed. Статусы отклика и переходы подробно описаны в MVP; перед реализацией читать его актуальную версию. Не подменять предложения утверждёнными требованиями.

12 предложенных сущностей: User, CandidateProfile, Resume, WorkExperience, Education, Skill, Company, CompanyMember, Vacancy, Application, CreditAccount, CreditTransaction. Связующие: ResumeSkill, VacancySkill. Таблицы Identity не используются как основной способ выполнить учебное требование по количеству сущностей.
