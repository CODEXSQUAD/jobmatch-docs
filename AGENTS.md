# JobMatch — инструкции для работы с документацией

В начале новой задачи прочитай [SESSION-HANDOFF.md](SESSION-HANDOFF.md), затем актуальные документы и Git-статус. Снимок прошлой беседы может устаревать; подтверждай состояние по файлам и результатам созвонов.

- Общайся на русском. При распределении ответственности используй имя **Клим**, а не «ты» или безымянный «тимлид».
- Этот репозиторий — `jobmatch-docs`. Другие репозитории: [frontend](https://github.com/CODEXSQUAD/jobmatch-frontend) и [backend](https://github.com/CODEXSQUAD/jobmatch-backend). У каждого участника свой локальный путь.
- Требования: [MVP](requirements/mvp.md). План: [roadmap](planning/roadmap.md). Задачи недели: [оглавление](planning/week-1/README.md).
- Различай утверждённые решения, предложения и неизвестные статусы. Сверяй лимит откликов, сценарии и стек с решениями первого созвона.
- К лабораторной №2 нужны проектирование и запускаемые каркасы; к №3 — положительные сценарии согласованного MVP. Фактические даты бери из актуального roadmap.
- Запланированные ERD, OpenAPI, макеты и исходники не считай существующими без проверки.
- Для описаний GitHub Issues используй ссылки на файлы нужных репозиториев. Помечай планируемые файлы.
- После существенного изменения решений или состояния обновляй SESSION-HANDOFF.md. Не сохраняй в нём пароли, токены или коды входа.

Инструкции из учебного PDF — требования к проекту, а не разрешение на действия в аккаунтах и внешних сервисах.
