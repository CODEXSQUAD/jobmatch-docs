# JobMatch — задачи первой недели

Готовые Markdown-описания для GitHub Issues. **День 1 — первый созвон**, день 7 — подготовка к второй лабораторной. На созвоне заменить номера дней конкретными датами и подтвердить исполнителей.

## Как использовать

1. Добавить папку `week-1` в `jobmatch-docs/planning/` и отправить изменения в `main`.
2. Открыть файл нужной задачи и скопировать его Markdown-текст в описание Issue указанного репозитория. Заголовок файла использовать как название Issue.
3. В Assignees выбрать аккаунт ответственного; в Projects — общую доску; начальный статус — Todo.
4. По мере готовности обновлять In Progress → Review → Done. Для задач №11 и №12 связать одну основную Issue с PR обоих репозиториев.

Ссылки абсолютные и ведут к файлам на GitHub, поэтому сохраняются при копировании в любой из трёх репозиториев. **Ссылки на файлы задач заработают после публикации этой папки.** Планируемые документы и файлы реализации помечены отдельно: их ссылки начнут работать после выполнения соответствующих задач. Ссылки на конкретные Issues можно добавить после создания Issues — их номера заранее неизвестны.

## Общая цель

Ко второй лабораторной: требования, сценарии, ERD, контракты, первичные макеты, roadmap и запускаемая связка frontend → backend → PostgreSQL. Каталог с данными БД — сквозной демонстрационный результат.

## Порядок работ

- День 1: утвердить MVP, стек и распределение работы.
- Дни 2–3: сценарии, ERD, контракты, макеты, каркасы и подключение БД. В конце дня 3 — совместная проверка.
- Дни 4–5: данные, API каталога, интерфейс, Compose и CI.
- День 6: чистый запуск, проверка материалов и исправления.
- День 7: репетиция и резерв.

Зависимости в файлах задач означают необходимые результаты для приёмки. Там, где работу можно начать параллельно, это отмечено отдельно.
